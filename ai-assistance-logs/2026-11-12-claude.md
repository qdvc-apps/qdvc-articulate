### Choice of model

I'd use Gemma 4 E4B rather than Gemma 3n E4B. Google released Gemma 4 on April 2, 2026, in four sizes: E2B (2.3 billion effective parameters), E4B (4.5 billion), a 26B mixture-of-experts model and a 31B dense model. It's also the first Gemma family released under the OSI-approved Apache 2.0 licence. Two practical points:
- **llama.cpp version:** release b8637 is the first one with Gemma 4 support, so use b8637 or newer.
- **Prompt format:** Gemma 4 uses new control tokens, so the app formats prompts itself rather than relying on llama.cpp's built-in template list. It detects Gemma 4, Gemma 2/3, Qwen (ChatML), Llama 3, Mistral and Phi from the GGUF file.

The alternatives I considered and didn't pick:
- **Apple Foundation Models:** needs no model file, but requires macOS 26 on a Mac with Apple Intelligence turned on, and it locks you to Apple.
- **Harper:** an offline English grammar checker written in Rust. It's good, but it's another project to depend on, which you wanted to avoid.

### How the app is put together

- **Network isolation:** the app runs in Apple's App Sandbox with no network permission, so macOS itself refuses every connection, including any llama.cpp might try. The build script stops if a network permission is ever added. The app also checks this when it starts, and Settings → Privacy has a live connection test (to 127.0.0.1, so nothing could leave the Mac even if it got through).
- **Checks while you type:** about 20 rules (a/an, "could of", then/than, repeated words, capitalisation, spacing, unmatched brackets, US/UK/Canadian/Australian spelling, wordiness, clichés, passive voice, long sentences, formality), plus the built-in macOS spell checker.
- **AI review (⇧⌘K):** works paragraph by paragraph and shows results as each one finishes. The model is forced to answer in a fixed format, so it can't ramble or return broken output. Paragraphs you haven't changed aren't sent to the model again.
- **Ready for Linux and Windows:** all the checking logic is in a separate module with no Mac-specific code, so a port only needs a new interface on top.

### Things to check on your first build

- **llama.cpp code:** everything that talks to llama.cpp is in one file, `LlamaEngine.swift`. The setting I'm least sure of is `swa_full`. If your llama.cpp version has renamed it, that file will show the error.
- **Undo:** check that one Undo step undoes one edit. The editor and the document system could both be recording undo steps.
- **Signing:** the default build is signed without a certificate. If the sandboxed app won't launch, build with your own certificate: `SIGN_IDENTITY="Apple Development: …" scripts/build-app.sh`.
- **macOS spell checker:** it runs as a system service outside the app's sandbox. It works offline, but you can switch it off in Settings → General.
